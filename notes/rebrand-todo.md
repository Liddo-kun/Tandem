## Auto-update plan (item E)

Current behavior (`packages/opencode/src/cli/upgrade.ts`, called from TUI worker on startup `upgrade().catch(() => {})`):
- Checks latest release from `https://api.github.com/repos/anomalyco/opencode/releases/latest` (**official opencode**, in `packages/opencode/src/installation/index.ts:264`).
- Already guarded by `config.autoupdate === false` and `Flag.OPENCODE_DISABLE_AUTOUPDATE`; raw-binary installs report `method === "unknown"` so it won't silently overwrite — but it **will** show misleading "official opencode update available" notifications to Tandem users.

**Decision: disable auto-update/notify for Tandem.** Lowest-surgery, lowest merge-conflict option: a single brand-guarded early `return` at the top of `upgrade()` (marked `UPSTREAM-DIVERGENCE`), or default `autoupdate` off for the Tandem build. This avoids misleading prompts and any chance of pulling official opencode over Tandem.

**Future option (NOT now):** GitHub-based auto-update from `Liddo-kun/Tandem` releases. Requires (1) repointing the releases URL to the Tandem repo and (2) a real binary-asset download/replace path (the existing npm/brew/choco/scoop methods don't apply to a raw tablet binary), plus an actual Tandem release pipeline. That's moderate surgery and adds merge friction, so it's deferred until Tandem publishes releases.
