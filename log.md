## Safety Filter Notice

- Surfaces provider safety-filter blocks that otherwise produce a silent empty assistant turn. Anthropic's Fable 5 (and similar Mythos-class models) end flagged cybersecurity/biology requests with `stop_reason: "refusal"`, which both Tandem runtimes map to `finishReason: "content-filter"`; because Tandem does not opt into the `server-side-fallback-2026-06-01` beta, there is no auto-switch to Opus and no notice — the user just sees a blank turn. The session processor now emits one additive `text` part when a step finishes with reason `content-filter`, telling the user the response was blocked and to retry on another model (e.g. Opus 4.8). Marked `UPSTREAM-DIVERGENCE`, gated solely on `value.reason === "content-filter"`, so it is inert for all normal finishes and safe to drop on upstream merge. File: `packages/opencode/src/session/processor.ts`.

## Prompt Corrector

- Adds a Tandem-only built-in plugin that runs each outgoing user prompt through a cheap "corrector" model (spelling/punctuation/voice-transcription fixes, minimal structure fixes) and hides a "RePrompt" duplication for short prompts. The corrector spawns a throwaway session whose system prompt is fully replaced (via `experimental.chat.system.transform`, keyed on the corrector's own session ID) and whose tools are disabled, so it corrects text instead of acting on it. The throwaway session is created as a child (`parentID`) of the session being corrected so it stays out of the UI's root session lists and post-delete navigation (its create/delete churn can never be tabbed or leave ghost tabs); debug mode keeps sessions at root level so they stay visible for inspection. Self-contained in a new file with env toggles (`TANDEM_PROMPT_CORRECTOR`, default on; `TANDEM_PROMPT_CORRECTOR_DEBUG` keeps corrector sessions; `TANDEM_PROMPT_CORRECTOR_REPROMPT_MAX`). Files: `packages/opencode/src/plugin/prompt-corrector.ts` (new).
- Divergence: registers that plugin in `internalPlugins()` so it ships enabled by default (one import + one array entry, both marked `UPSTREAM-DIVERGENCE`). Files: `packages/opencode/src/plugin/index.ts`.
- Divergence: for corrector turns, skips the `AGENTS.md`/instruction `<system-reminder>` injection so the spawned corrector model receives only the raw user text (detected via the `tandemPromptCorrector` part-metadata marker on the message part). Files: `packages/opencode/src/session/prompt.ts`.
- Disabled for the `tandem run` CLI command: non-attach `run` hosts the server in-process and blocks on the prompt request, and the corrector's nested `session.prompt` hangs it. The plugin detects the `run` command via `process.argv` (first non-flag token) and returns no hooks; `run --attach` uses a separate `serve` process where the corrector remains active. Files: `packages/opencode/src/plugin/prompt-corrector.ts`.
- Full behavior (dictated-path/technical cleanup, RePrompt gating, the faithfulness safety net that discards non-copy-edits, and all env vars incl. `TANDEM_PROMPT_CORRECTOR_REPROMPT_MIN`/`_MAX`) is documented in `PromptEnhance.md`.

## Image Generation (imagegen)

- Adds a Tandem-only built-in `imagegen` tool (generate or edit raster images via OpenAI) that returns a saved PNG plus an inline `data:` image attachment. Self-contained in a new directory; reuses the existing plugin `tool` hook so no upstream tool/registry files change. Model-facing args: `prompt`, `quality` (`low|medium|high|auto`, default `high`), `size` (`auto|1024x1024|1536x1024|1024x1536`, default `auto`), `n` (1-10, default 1), `image_paths` (≤10 local files → edit mode), `mask_path` (optional, API-key path only). Files: `packages/opencode/src/plugin/openai/imagegen/imagegen.ts`, `imagegen.txt`, `plugin.ts` (all new).
- Two transports by auth mode (resolved at execute time): **API key** (`Auth` store `openai` type `api`, or `OPENAI_API_KEY`) → REST `POST api.openai.com/v1/images/{generations,edits}` with model `gpt-image-2` (generations JSON, edits multipart, `data[].b64_json`); **ChatGPT OAuth** (`openai` type `oauth`) → the OpenAI Responses built-in `image_generation` tool over `POST chatgpt.com/backend-api/codex/responses` (the ChatGPT backend has no REST images route), with `stream:true`+`store:false`, `tools:[{type:"image_generation",size,quality,output_format:"png",moderation:"low"}]`, `tool_choice` forced, edits via `input_image` data-URL parts; the base64 PNG is read off the SSE `response.output_item.done` (`item.result`). Contract is live-verified; details in `notes/imagegen.md`.
- Visibility (option A): the plugin reads the auth store directly (the SDK client exposes no auth read path) and only contributes the `imagegen` tool when an OpenAI credential resolves at construction, so it stays hidden when no OpenAI creds exist; per-request re-evaluation on later login is deferred. OAuth tokens are refreshed-if-stale at execute time and persisted via `client.auth.set`. Reuses `extractAccountId` from `../codex`; the small OAuth refresh + client id/issuer are duplicated locally so `codex.ts` needs no edits. Env toggle `TANDEM_IMAGEGEN=0` disables it; `TANDEM_IMAGEGEN_OAUTH_MODEL` overrides the OAuth host model (default `gpt-5.5`). Saves artifacts non-destructively under `Global.Path.data/imagegen/<sessionID>/`. Tool-result attachments are not pipeline-normalized and `Image.normalize` is unreachable from a plugin, so raw PNGs are returned as-is.
- Divergence: registers the plugin in `internalPlugins()` (one import + one array entry, both marked `UPSTREAM-DIVERGENCE`). Files: `packages/opencode/src/plugin/index.ts`.
 - Web UI inline render: tool-result image attachments were delivered to the client (`ToolStateCompleted.attachments`) but never drawn — the tool-card path didn't pass `attachments` to renderers, and an unregistered tool fell back to `GenericTool` (title only). Fixed in the web UI (`@opencode-ai/ui`, shared by the Android/iOS apps): `ToolProps` now carries `attachments`, `ToolPartDisplay` threads `part.state.attachments` into the rendered component, and a Tandem-only `imagegen` `ToolRegistry` renderer shows the PNG(s) inline (click → `ImagePreview` lightbox), reusing the same `data:` image display as user attachments. All three touches marked `UPSTREAM-DIVERGENCE`. Files: `packages/ui/src/components/message-part.tsx`. (The TUI, `packages/tui`, is a separate terminal renderer and does not show inline images.)
 - OAuth verbatim prompt + revised-prompt surfacing: on the OAuth path the host chat model (`gpt-5.5`) authors the prompt handed to the `image_generation` tool and, left to itself, rewrites/expands and sanitizes it (proven by Codex `responses` traces — default turns "girl" into "adult woman", verbatim only when explicitly told; see `notes/imagegen.md`). The OAuth `instructions` now force exact pass-through of the user's wording. Separately, the prompt the image model reports it actually used (`revised_prompt`) is captured per image — on OAuth from the SSE `image_generation_call` item, on the API-key path from `data[].revised_prompt` — threaded through `run()`/`execute` into `metadata.revisedPrompts` (aligned with the images) and appended to the tool `output` only when it differs from the typed prompt. The web UI `imagegen` renderer shows that revised prompt as a small "Prompt used:" caption under each image when it differs. Files: `packages/opencode/src/plugin/openai/imagegen/imagegen.ts` (tightened `instructions`, new `GeneratedImage` return type, `revised_prompt` capture), `plugin.ts` (`revisedPromptOutput`, `metadata.revisedPrompts`), `packages/ui/src/components/message-part.tsx` (caption).
 - Image no longer fed into model context: the tool result no longer returns the PNG as an `attachment`. Tool-result attachments are converted into model vision input (`session/message-v2.ts:307-322` — embedded in the tool result or re-injected as a user message) and re-sent every turn, so a full PNG ballooned context. `metadata` is unsafe for the image too (it is forwarded verbatim as `callProviderMetadata` via `providerMeta`). The tool now returns only the saved file path(s) as text `output` (plus a note that the image is not in context and can be opened with `read`); the model decides for itself whether to view it via the `read` tool (which loads images). Server-side only (no UI/APK change). Side effect: the web UI no longer auto-renders the PNG inline for imagegen (the `message-part.tsx` renderer just has no attachments to draw); the `ToolProps.attachments` threading remains in place and harmless. Files: `packages/opencode/src/plugin/openai/imagegen/plugin.ts` (removed `attachments`, path-only `output`), `imagegen.txt` (description).
 - Built-in `imagegen` skill, gated exactly like the tool: a Tandem skill is embedded in the binary (body in `packages/opencode/src/plugin/openai/imagegen/imagegen-skill.md`, imported as text via the existing `*.md` ambient module; name/description live in code as `ImageGen.SKILL`) and registered in the v1 skill service next to the built-in `customize-opencode` (`packages/opencode/src/skill/index.ts`, `UPSTREAM-DIVERGENCE`, before disk discovery so a user-disk `imagegen` skill still overrides it). Visibility uses one shared gate, `ImageGen.isAvailable()` = opt-out flag `TANDEM_IMAGEGEN=0` not set **and** a resolvable OpenAI credential; `plugin.ts` now gates the tool on the same function, so skill and tool can never disagree (evaluated once per instance like the tool, so a later login needs a server/instance restart to surface either). The skill content covers prompt authoring (the model writes the full prompt; verbatim transport preserves it), generate-vs-edit with local-file-only edit inputs + `mask_path`, the no-transparency constraint, and that the saved image is not fed into context (open with `read`). Live-verified against the built binary: embedded body present, skill listed with creds and correctly absent under `TANDEM_IMAGEGEN=0` or with no OpenAI creds. Files: `packages/opencode/src/plugin/openai/imagegen/imagegen-skill.md` (new), `imagegen.ts` (`SKILL`, `isAvailable`, `disabledByFlag`), `plugin.ts` (shared gate), `packages/opencode/src/skill/index.ts` (gated built-in registration).
 - Web UI thumbnails without re-entering model context: generated images now show as click-to-zoom thumbnails in the tool card while still keeping the bytes out of the model's context. The decoupling: the tool result still carries only the relative path(s) (no attachment, no image in `metadata`), and the **browser** fetches each PNG on its own — a render-time fetch that never touches the model loop. To make those bytes reachable through the existing worktree-scoped `file.read` endpoint, `saveImages` now writes under `<sessionDir>/imagegen/<sessionID>/` (the session's working folder) instead of `Global.Path.data/...`, and returns paths **relative** to that dir (posix separators) so the same string works for both `file.read` in the UI and the `read` tool for the model; users can `.gitignore` `imagegen/`. The UI plumbs a worktree-scoped reader through the Data context: `useData().readFile` (optional `(path) => Promise<FileContent|undefined>`, `UPSTREAM-DIVERGENCE`), supplied by the app from `sdk().client.file.read` in `DirectoryDataProvider` (inside `SDKProvider`). The Tandem `imagegen` `ToolRegistry` renderer fetches each path via that reader (`createResource` → `dataUrlFromMediaValue`) and renders an `<img loading="lazy">` thumbnail that opens the existing `ImagePreview` lightbox on click, with the path + differ-only "Prompt used:" caption beneath. Built into the binary + embedded web UI (`build --single` smoke pass). Files: `packages/opencode/src/plugin/openai/imagegen/imagegen.ts` (`saveImages` dir + relative paths), `plugin.ts` (pass `ctx.directory`), `packages/ui/src/context/data.tsx` (`readFile`), `packages/app/src/pages/directory-layout.tsx` (supply `readFile`), `packages/ui/src/components/message-part.tsx` (`ImagegenThumb` + renderer), `packages/ui/src/components/message-part.css` (thumbnail styles).
 - Honest size reporting (OAuth ignores `size`): on the ChatGPT/OAuth backend the `image_generation` tool **ignores the requested `size`** entirely — the host model auto-sizes from the prompt and even returns non-enum dimensions (live-probed: a landscape prompt at `size:1024x1024` → 1536x1024; a portrait config on the same prompt → still 1536x1024; a square-cued prompt → 1254x1254; and an end-to-end `run()` → 1402x1122). A forceful size `instructions` directive does **not** help (unlike the verbatim-prompt trick). The tool used to mislabel the result with the *requested* size. Fix: new `ImageGen.pngDimensions(buf)` reads the real width/height from each PNG's IHDR header, and `plugin.ts` reports those **actual** dimensions in the output label and `metadata.size`, adds `metadata.requestedSize` + per-image `metadata.sizes`, and appends a one-line note when an OAuth request's size was dropped (so the agent doesn't retry the same size). The model-facing `size` field description and the built-in skill now state size is exact only with an API key and best-effort (steer via the prompt) on OAuth. API-key path is unchanged (size is honored there). New unit test `test/plugin/imagegen.test.ts` covers `pngDimensions`. Files: `packages/opencode/src/plugin/openai/imagegen/imagegen.ts` (`pngDimensions`), `plugin.ts` (actual-size label/metadata/note + field describe), `imagegen-skill.md` (size caveat), `test/plugin/imagegen.test.ts` (new).
