## Maintenance and GitHub releases

1. **With each change:** add a dated Unreleased entry describing the user-visible result (Added, Changed, Fixed or Removed). Include platform/opt-in limits and a commit reference when available; otherwise the entry's own commit provides provenance. Material maintenance and documentation changes may use those labels. Use implementation dates; identify historical backfills as Git dates. Do not infer publication from a local build.
2. **Keep the inventory current:** revise matching divergence entries when shared-file behavior or fork-owned file ownership changes. Keep implementation detail in the inventory/feature reference. User-visible changes inside existing fork-owned features still belong in release history even if the inventory needs no update. Mobile-app changes get concise release entries here and detailed history in `tandem-changelog.md`.
3. **Prepare a release:** select the target commit and previous **Tandem** tag; review their Git range against Unreleased entries and the mobile changelog. Separate Tandem enhancements from the upstream-baseline note. Include only changes present in the target and describe only artifacts actually built. Use the feature overview for an optional "About Tandem" section, not a list of new features.
4. **Record the version:** move included dated entries into `### <Tandem tag> — YYYY-MM-DD` under Release history, retain implementation dates, and record the target commit, upstream baseline and GitHub URL. Leave a fresh Unreleased section based on that tag, retaining excluded work there. Publication date is the actual UTC GitHub date. Preserve published history; later reversals/fixes get new entries.
5. **Publish notes:** compose that version's user-facing notes into Markdown and supply them to `gh release create <tag> --repo Liddo-kun/Tandem --target <commit> --notes-file <file>` when publication is requested. Always specify the repository: this checkout also has the OpenCode upstream remote. Existing `script/changelog.ts` / `script/version.ts` follow the upstream changelog path and do not extract this log; `tandem:release` / `tandem:package --upload` build/package or upload assets, not these notes. This reorganization does not change those scripts or publish a release.

### Claude Bash-Search (CC-style Glob/Grep removal)

- Adds an opt-in Tandem-only feature (`TANDEM_CLAUDE_BASH_SEARCH=1`, default off) mirroring real Claude Code v2.1.117+: Claude models get no Glob/Grep tools and search via plain `grep`/`find` in Bash, which are silently upgraded to ugrep/bfs — no prompt-text steering, the environment is the steering. Fork-owned plugin `packages/opencode/src/plugin/bash-search/` (`bash-search.ts` core + `plugin.ts`) writes PATH shim scripts to `<Global.Path.bin>/shims` at construction (opencode spawns a fresh shell per command, so CC's shell-function approach cannot work; shims ride the existing `shell.env` hook, prepending the shim dir to PATH for spawned commands only). Shim flags and the grep fallback are copied verbatim from CC 2.1.220's shell-snapshot functions captured on this tablet: `grep` → `ugrep -G --ignore-files --hidden -I --exclude-dir={.git,.svn,.hg,.bzr,.jj,.sl}` with a pre-flight arg scan that falls through to the real system grep on ugrep-incompatible/dangerous flags (`--filter`, `--pager`, `-Z*` fuzzy, `--null`, …); `find` → `bfs -S dfs -regextype findutils-default` (regextype probed at generation — bfs < 3.2 lacks `findutils-default`, falling back to `emacs`, then none; Ubuntu 24.04 ships bfs 3.1.2). Binaries are provisioned out of band (`apt install ugrep bfs` / `brew install ugrep bfs`); runtime only detects them via `which()` — when the flag is off, on win32, or a binary is missing, the feature is fully inert (shims unwritten, tools kept, no errors). Tool removal is gated on `BashSearch.isActive()` (shims confirmed written) so a Claude model is never stranded with neither tools nor upgraded search; activation is evaluated once per process (restart after installing binaries, same semantics as imagegen credentials). When active for a Claude model, the registry also strips the now-stale "File search: use Glob" / "Content search: use Grep" bullets from the shell tool's dedicated-tools list per-request (`BashSearch.stripSearchBullets`), so the description never steers at tools the model doesn't have; other models and inactive sessions keep the full list. Tests in fork-owned `test/plugin/bash-search.test.ts` (gate matrix, shim generation, live shim execution incl. fallback, registry filtering, description strip); live-verified on the tablet (flag on: `grep --version` → ugrep, `find --version` → bfs, no Glob/Grep in a Claude session; flag off: GNU grep, tools present). Design: `notes/plan-bash-search.md`. Files: `packages/opencode/src/plugin/bash-search/bash-search.ts` + `plugin.ts` (new, fork-owned), `test/plugin/bash-search.test.ts` (new, fork-owned); `UPSTREAM-DIVERGENCE`-marked edits in upstream-shared `packages/opencode/src/plugin/index.ts` (registration) and `packages/opencode/src/tool/registry.ts` (Glob/Grep filter + shell-description strip).
- Divergence in upstream-shared files, both `UPSTREAM-DIVERGENCE`-marked: registers `BashSearchPlugin` in `internalPlugins()` (one import + one array entry, next to PromptCorrector/Imagegen) in `packages/opencode/src/plugin/index.ts`; and one filter block in `ToolRegistry.tools()` (next to upstream's per-model `usePatch` precedent) dropping `glob`/`grep` when `BashSearch.isActive() && modelID.includes("claude")` (covers anthropic/bedrock/vertex ids) in `packages/opencode/src/tool/registry.ts` (plus its marked import).

Model-facing args mirror the built-in (`url`, `format` `text|markdown|html`, `timeout` ≤120) plus optional `prompt` (what to extract; omitted → full main content). Opt out with `TANDEM_BROWSER_FETCH=0` (leaves the built-in in place). Files: `browser-fetch/plugin.ts`, `webfetch.txt` (tool description), `web-fetcher.md` (subagent prompt, embedded via the `*.md` text import), `cdp-fetch.ts` (engine + CLI).
- Engine `cdp-fetch.ts` is dependency-free raw Chrome DevTools Protocol over Bun's WebSocket: Tier 1 the headed desktop Chromium on Termux:X11 (`~/.local/bin/chromium-x`, CDP `127.0.0.1:9223`, the user's real profile — logged-in views, JS rendered; auto-launched if the X display is up; the launch is serialized across concurrent fetches and skipped when a live Chromium already owns `~/.config/chromium/SingletonLock`, since parallel `webfetch` calls each launching against the same profile produced a browser per call and a "Profile error occurred" window per tab), Tier 2 (`android`) stock Android Chrome via `adb forward tcp:9222 localabstract:chrome_devtools_remote` (auto-forwarded through the `adb-reconnect` helper). Tabs are opened/closed with `Target.createTarget`/`Target.closeTarget` on the browser websocket (Android Chrome refuses HTTP `/json/new`) and always closed on any exit path (hard timeout, abort, error) so no half-loaded tab is stranded in the visible window. Waits for load then polls a placeholder-text regex (`PENDING_RE`) for up to 30 s so sites that first serve an interstitial and then swap in the real page are read after the swap; result carries `pageState` `ready|ready-after-wait|never-ready`. Same file is executable as the `cdp-fetch` CLI (`--html --links --screenshot --android --endpoint --timeout --settle --keep-tab --json`; exit 0 ok / 1 error / 2 usage / 3 hard timeout / 4 never-ready), symlinked at `~/.local/bin/cdp-fetch` for manual use. Never call `/json/list` from agent flows (dumps the user's whole tab list into context).
- Engine waits for the main frame to load _and stay put_ (tracks `frameStartedLoading`/`frameScheduledNavigation` via `Page` events, so meta-refresh/JS redirects and "redirecting, please wait" pages are followed rather than captured), records the main document's HTTP status via `Network.responseReceived` (`HTTP 404` etc. surfaced in the header so the subagent knows it is looking at an error page), recognises rate-limit pages (`pageState: "blocked"`, CLI exit 5; not retried on Android, reported to the subagent as "do not retry this site"), and handles document downloads: a navigation that becomes a download (`net::ERR_ABORTED` + `Document` response with PDF/octet-stream/attachment) is refetched by us with the browser's cookies into `/tmp/tandem/webfetch/`, PDFs run through `pdftotext -layout`; `Page.setDownloadBehavior deny` keeps Chrome from also saving a copy to `~/Downloads`. `Page.navigate` gets 60% of the remaining budget instead of the fixed 15 s CDP command cap.
- Subagent budget: inside `web-fetcher`, raw-mode fetches are capped per child session (`MAX_FOLLOWUPS` 12, of which at most `MAX_SEARCHES` 5 may be search-engine URLs, `SEARCH_RE`); over budget the tool errors with "answer from what you already have". Motivation: a 404 starting URL once turned into 68 fetches / 46 Google searches and got the network's IP onto Google's "unusual traffic" page.
- Flow: the plugin fetches inline (deterministic retries in code: exit-3 timeout → one retry at 120 s; `never-ready` on desktop → one retry on Android Chrome), fails fast with `Fetch failed for <url>: …` without spending a subagent turn, caps content at 100 KB, then creates a child session (`parentID` = caller, title `fetch <host>`) and prompts the `web-fetcher` subagent with URL/format/prompt + the page in `<page>` tags, returning the last text part. The prompt part carries `metadata.tandemCorrectorDisabled` because the prompt corrector's no-`model` fallback path fails and retries for ~70 s (see Prompt Corrector). Inside the subagent the same tool runs in raw mode (`context.agent === "web-fetcher"` → returns the rendered page, no child session), which is both the recursion guard and the subagent's follow-up mechanism (different URL, `format: "html"` for markup-only state like edit notices or counts). Verified live: a voz.vn thread question completes in 2 subagent turns / ~21.7K input tokens (was 3 turns / 29K when the subagent issued the fetch itself).
- Subagent `web-fetcher` is injected by the plugin's `config` hook (`cfg.agent["web-fetcher"] = { ...defaults, ...user }`, so any user `agent.web-fetcher` config field overrides): `mode: subagent`, `hidden: true`, `openai/gpt-5.6-sol` variant `medium`, temperature 0.1, permissions `* deny` then `fetch_page allow`, `read allow` (screenshots and overflow files). The hook also denies `task["web-fetcher"]` globally: `hidden` only hides the UI entry, while Task permissions keep this internal reader out of the model-facing subagent catalog and disallow direct Task dispatch. Existing task shorthand/pattern rules are retained; the reader-specific deny is appended after wildcards. `webfetch` still creates and prompts the child directly. The hook receives the live config object; if upstream ever hands plugins a copy, `webfetch` fails loudly with an agent-not-found error rather than silently degrading. Regression coverage: `packages/opencode/test/plugin/browser-fetch.test.ts`.
- Web UI: the built-in `webfetch` renderer (`hideDetails`, output hidden) is replaced with a Bash-style `ToolSummaryTrigger` card — first line of the answer as preview, full Markdown answer when expanded, URL link in the body — since the output is now the answer rather than a raw page dump. File: `packages/session-ui/src/components/message-part.tsx` (`webfetch` renderer).
- Every fetch captures the rendered page as full-page PNG slices (1 CSS px per image px, 1600px per slice, max 4, `Page.captureScreenshot` with `captureBeyondViewport`) into `/tmp/tandem/webfetch/` (pruned to the newest 300). The subagent's page header lists them neutrally and its prompt says when they are worth a `read` (charts, image-baked specs, positional layouts). `screenshot: true` on the tool attaches the slices as image parts in the subagent's first message so it answers in one turn. Paths are appended to the caller's answer either way. `cdp-fetch --screenshot` does the same from the CLI.
- The subagent's follow-ups go through its own `fetch_page` tool (same engine, returns the page, honest description). The plugin's config hook adds a global `fetch_page: deny` so no other agent sees it; the subagent's permission re-allows it and denies `webfetch`, which is the recursion guard. Its prompt part carries `metadata.tandemBareContext`, which `session/prompt.ts` honours by dropping AGENTS.md, the scratchpad block, and project references from the system prompt (only the model/date line stays); `options.textVerbosity: "medium"` overrides the gpt-5 default of `low`. An initial page over 100 KB spills to `<ts>-<host>.txt` beside the screenshots.
- `TANDEM_DUMP_REQUEST=<dir>` (`session/llm.ts`) writes every prepared model request — system, messages, tool schemas, params — as one JSON file per call, for auditing what a model is actually sent.
