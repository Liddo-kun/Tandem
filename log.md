# Tandem Change Log

This log is the final-state inventory of Tandem changes relative to official OpenCode.
Document current deltas only: no skipped commits, no OpenCode merge history, and no superseded behavior.
Each entry is a live divergence — an upstream-shared file Tandem modifies, or a fork-owned file Tandem adds — not a change event. When a divergence's behavior changes, rewrite its entry to the new state instead of appending a bullet. A change to already fork-owned code that does not alter the divergence surface (e.g. tuning an existing Tandem-only plugin or tool) is recorded in that feature's own doc, not here.
For each item, reference the modified files or stable symbols; line numbers are optional and may drift.
The mobile app packages (`packages/android`, `packages/ios`) are Tandem-owned product code inherited from the discontinued Whispercode project, not divergence — they are documented in `tandem-changelog.md` instead. Entries here still cover every upstream-shared file the apps depend on (platform contract, shared mobile UI, rebranding seams), and may reference app-package files as feature context.

- Transparent-background cutouts (`transparent: true`): gpt-image-2 and the OAuth `image_generation` tool can't emit alpha natively, so transparency is produced by the Codex imagegen skill's built-in workflow — render the subject on a flat solid chroma-key background, then key that color out to alpha locally. `chroma.ts` is a native-TypeScript port of Codex's `remove_chroma_key.py` (auto-key border sampling via per-channel median, soft-matte alpha ramp, key-dominance test, despill, edge contract/feather; same defaults `--auto-key border --soft-matte --transparent-threshold 12 --opaque-threshold 220 --despill`), running on raw RGBA from the already-bundled **Photon** WASM codec (`get_raw_pixels` → mutate alpha → `new PhotonImage` → `get_bytes`) — **no Python/Pillow runtime dependency**. `ImageGen.run()` appends `Chroma.PROMPT` (a flat-key-background directive; appended to the prompt, not the system message, so it survives the OAuth verbatim pass-through) and post-processes each returned PNG through `Chroma.removeChromaKey`; `revisedPrompt` is dropped for transparent calls (it would just echo the chroma directive). Works on both transports and with edits (`image_paths` + `transparent`). Clean for solid-edged subjects; wispy edges (hair/fur/glass/smoke) may fringe — documented in the model-facing `transparent` arg description and the skill's "Transparent backgrounds" section. Native `gpt-image-1.5 background:transparent` (true alpha for wispy subjects, API-key only) is deliberately left as a future opt-in so the default keeps the better gpt-image-2 image and works on OAuth. Perf: full 1536×1024 keys in ~110ms. Tests in `test/plugin/imagegen.test.ts` build a fixture via Photon and assert corners→transparent, subject→opaque, no green fringe. **Bright-rim halo handling:** the image models paint a thin near-white "sticker outline"/rim-light glow where the subject meets the key color — that rim isn't key-colored, so pure chroma keying leaves it opaque (a chroma-key limit, not a port bug; Codex relies on an agent re-running with `--edge-contract`). Fixed unattended two ways: (1) `Chroma.PROMPT` now forbids outline/stroke/sticker-border/white-edge/halo/rim-light/glow/light-wrap around the silhouette; (2) new automatic `defringeBrightRim` pass (default on, `DEFRINGE_*` constants) erodes 2 one-pixel rings of any matte-boundary pixel that is bright (mean RGB ≥ 200) **and** desaturated (HSV S < 0.15), eating the grey/white rim while sparing saturated colored edges and thin features. Tuned offline on the real keyed PNG, confirmed on a fresh live gen (opaque white-rim px 2419→845, no visible halo over magenta). Genuinely-white subjects are the irreducible case → future `gpt-image-1.5` opt-in. Tests `defringe erodes…`/`defringe can be disabled` added (10 pass). Files: `packages/opencode/src/plugin/openai/imagegen/chroma.ts` (new), `imagegen.ts` (`Args.transparent`, transparent branch in `run`/`generateOrEdit`, `encodeWebp`), `plugin.ts` (`transparent` arg/schema/metadata/label), `imagegen-skill.md` (Transparent backgrounds section).

## Claude Bash-Search (CC-style Glob/Grep removal)

- Adds an opt-in Tandem-only feature (`TANDEM_CLAUDE_BASH_SEARCH=1`, default off) mirroring real Claude Code v2.1.117+: Claude models get no Glob/Grep tools and search via plain `grep`/`find` in Bash, which are silently upgraded to ugrep/bfs — no prompt-text steering, the environment is the steering. Fork-owned plugin `packages/opencode/src/plugin/bash-search/` (`bash-search.ts` core + `plugin.ts`) writes PATH shim scripts to `<Global.Path.bin>/shims` at construction (opencode spawns a fresh shell per command, so CC's shell-function approach cannot work; shims ride the existing `shell.env` hook, prepending the shim dir to PATH for spawned commands only). Shim flags and the grep fallback are copied verbatim from CC 2.1.220's shell-snapshot functions captured on this tablet: `grep` → `ugrep -G --ignore-files --hidden -I --exclude-dir={.git,.svn,.hg,.bzr,.jj,.sl}` with a pre-flight arg scan that falls through to the real system grep on ugrep-incompatible/dangerous flags (`--filter`, `--pager`, `-Z*` fuzzy, `--null`, …); `find` → `bfs -S dfs -regextype findutils-default` (regextype probed at generation — bfs < 3.2 lacks `findutils-default`, falling back to `emacs`, then none; Ubuntu 24.04 ships bfs 3.1.2). Binaries are provisioned out of band (`apt install ugrep bfs` / `brew install ugrep bfs`); runtime only detects them via `which()` — when the flag is off, on win32, or a binary is missing, the feature is fully inert (shims unwritten, tools kept, no errors). Tool removal is gated on `BashSearch.isActive()` (shims confirmed written) so a Claude model is never stranded with neither tools nor upgraded search; activation is evaluated once per process (restart after installing binaries, same semantics as imagegen credentials). When active for a Claude model, the registry also strips the now-stale "File search: use Glob" / "Content search: use Grep" bullets from the shell tool's dedicated-tools list per-request (`BashSearch.stripSearchBullets`), so the description never steers at tools the model doesn't have; other models and inactive sessions keep the full list. Tests in fork-owned `test/plugin/bash-search.test.ts` (gate matrix, shim generation, live shim execution incl. fallback, registry filtering, description strip); live-verified on the tablet (flag on: `grep --version` → ugrep, `find --version` → bfs, no Glob/Grep in a Claude session; flag off: GNU grep, tools present). Design: `notes/plan-bash-search.md`. Files: `packages/opencode/src/plugin/bash-search/bash-search.ts` + `plugin.ts` (new, fork-owned), `test/plugin/bash-search.test.ts` (new, fork-owned); `UPSTREAM-DIVERGENCE`-marked edits in upstream-shared `packages/opencode/src/plugin/index.ts` (registration) and `packages/opencode/src/tool/registry.ts` (Glob/Grep filter + shell-description strip).
- Divergence in upstream-shared files, both `UPSTREAM-DIVERGENCE`-marked: registers `BashSearchPlugin` in `internalPlugins()` (one import + one array entry, next to PromptCorrector/Imagegen) in `packages/opencode/src/plugin/index.ts`; and one filter block in `ToolRegistry.tools()` (next to upstream's per-model `usePatch` precedent) dropping `glob`/`grep` when `BashSearch.isActive() && modelID.includes("claude")` (covers anthropic/bedrock/vertex ids) in `packages/opencode/src/tool/registry.ts` (plus its marked import).
