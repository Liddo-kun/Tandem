# Tandem v2 OpenCode Differences

> **This file is only a log of Tandem's customizations to OpenCode, as they exist in the code — like v1's `log.md`.** It is never a place for decisions, approvals, proposals, open questions, pending work or to-dos. Deferred work goes in `notes/todo-after-v2.md`; port planning and evidence go in `notes/`. When a customization is removed or reverted, delete its entry here.

This file is the inventory of what Tandem v2 adds to, or changes in, official OpenCode v2, for upstream syncs. Dated changes, published releases and the feature overview are in [changelogv2.md](changelogv2.md). v1's inventory stays in the v1 checkout's `log.md`.

## Maintenance

1. **Mark code:** every edit to an upstream-shared file gets an `UPSTREAM-DIVERGENCE: <why>` comment at the changed code. Files that cannot carry comments are inventoried here instead: JSON manifests, `bun.lock`, generated client output, model-facing prompt text and `AGENTS.md` files. Do not hand-edit generated client files; regenerate from `packages/client` after public contract changes.
2. **Upstream bugs need Jon's agreement:** do not fix behavior that is broken in pristine upstream without Jon's approval. Approved fixes use `UPSTREAM-DIVERGENCE(temporary)` and are listed in [Temporary Upstream Bug Fixes](#temporary-upstream-bug-fixes). Remove them, with their markers, when an upstream sync brings an equivalent fix.
3. **With each change:** revise the matching entry below when shared-file behavior or fork-owned ownership changes, and add a dated entry to [changelogv2.md](changelogv2.md).

- **Manual updates:** `Updater.Service`'s public boundary is inert. `run` does nothing, `check` reports unavailable with download guidance, and `latest`/`apply`/`upgrade` fail with that guidance. - **Parallel gzip for large responses:** upstream compresses a whole response in one call before sending its headers; a 42 MB session page of inline photos took 2.6 s. JSON and text responses of 1 MiB or more, for clients that accept gzip, are split into up to 8 slices compressed on separate threads. Each slice is primed with the 32 KiB before it and all but the last end with a sync flush, so they join into one standard gzip stream (same size, about 0.15 s). Separate concatenated gzip members are avoided because Chromium decodes only the first. Gzip, not brotli or zstd, because Android WebView accepts only gzip and deflate over plain HTTP. Smaller responses use upstream's compression. Files: fork-owned `packages/server/src/middleware/tandem-parallel-gzip.ts`; shared `packages/server/src/process.ts` (import and middleware line).
- **Unchanged by design:** `@opencode/*` package scopes, `OPENCODE_*` environment variables, provider IDs, wire fields, `opencode.json(c)` and `.opencode` conventions, the Basic-auth username `opencode`, ACP `AuthMethodID` and command IDs such as `opencode.update`.

### Prompt Corrector

- A fork-owned built-in plugin copy-edits a prompt's authored text in an auxiliary session before the main turn, only when the prompt's client explicitly enables it (`tandemCorrectorDisabled: false`, sent by the app's toggle). That session has no parent (its owner is recorded as `tandemAuxiliaryOwner`), because upstream reports every child session to its parent when it goes idle; it shows in session lists while it runs. It gets only correction instructions and the raw text, has no tools or project instructions, and is deleted afterward. Accepted corrections replace the stored text, and changed originals are kept in `tandemPromptCorrectorOriginal` metadata. Rejected, empty or failed corrections keep the original. Details (environment variables, length limit, model selection, acceptance rules, debug sessions): `notes/tandem-corrector.md`. Files: fork-owned `packages/core/src/plugin/tandem/{prompt-corrector,auxiliary}.ts`, `packages/util/src/tandem-auxiliary.ts`; shared `packages/core/src/plugin/internal.ts` (registration).
- **Prompts appear once admitted:** with the Corrector on, a sent prompt appears only once the server has admitted it, already corrected, instead of at once: the Corrector runs before admission, and until then the server could not move or delete the prompt, so its buttons failed. The client's prompt admission takes `optimistic: false` to skip its local row; the composer skips its timeline handoff, and upstream's display of a prompt held while agents and models load. Files: `packages/client/src/solid/data.ts`, `packages/app/src/composer/{submit,machine}.ts`.
- **Composer toggle:** a persisted per-client Corrector control, off unless enabled, stored as `settings.v3.general.corrector`. Its state is snapshotted into drafts and queued prompts (`tandemCorrectorDisabled` when off) and kept through queue edit/reorder/undo/resend; a failed or cancelled send puts its setting back into the draft with the prompt, so a retry keeps it. A queued prompt without the setting counts as off. Correction covers only authored text ranges. Files: `packages/app/src/composer/{machine,model,request,schema,state,submit}.ts`, `packages/app/src/session/composer/{queue,queue-machine}.ts`, `packages/app/src/settings/{model.tsx,general/general.tsx}`.

- **Presentation (fork-owned):** every Claude model gets a request shaped like Claude Code's, in the parts below. Files: fork-owned `packages/core/src/plugin/tandem/claude/{plugin,presentation,instructions,updates,workdir}.ts`, `packages/core/src/plugin/tandem/request-dump/transport.ts` (trace headers), `claude/anthropic.txt`; shared `packages/core/src/session/{context,model-request}.ts`.

  - **Instruction placement:** the rendered instruction baseline, found by upstream's `experimental.instructions` metadata on that system part, is placed like Claude Code 2.1.299's context: AGENTS.md files open the first user message as their own `<system-reminder>`, with Claude Code's opening line and `Contents of <path> (<kind>):` labels (the global file as user's private global instructions, others as project instructions), and the rest follows that message as a system message in Claude Code's order: environment, Code Mode catalog, MCP, references and skills guidance, other sources, date. After a summary written by another model's compaction both go to the first user message after the checkpoint, or ahead of the checkpoint's text when none follows; Claude's own compactions are laid out as below. Claude models without native mid-conversation system messages (before Opus 4.8 and Claude 5) or outside the `anthropic` provider get the rest as a second reminder instead. Durable instruction updates stay chronological. Skills are listed once, and Skill tool text points to that list.
  - **Environment block:** rendered as Claude Code's `# Environment` list ("Primary working directory", "Is a git repository: true/false", the workspace root only when it differs, Tandem's temporary-files line), and changes as `# Environment update` with only the changed fields and their previous values.
  - **Tool names:** tool names and selected keys are mapped to Claude Code forms, with structured reverse mapping before validation, permissions and execution.
  - **Bash tool:** when the shell is local bash (not remote workspaces or Windows), the shell tool is presented as Claude Code's lean Bash tool (adapted description that says a `cd` stays in effect instead of preferring absolute paths and that a foreground command still running at its timeout moves to the background, no `workdir`); the real tool keeps `workdir`, which is filled with the session's folder so that `cd` carries over between foreground commands, as in Claude Code. Each foreground call that ends in a different folder from where it started records it, as in Claude Code, through a `BASH_ENV` exit trap and its own capture file (skipped when a user `BASH_ENV` is set); the folder is kept in memory until restart, and reset to the session directory with a note if it disappears. The environment's working-directory line gets a note that the Bash tool starts there and keeps its folder, so `cd` before each command is unnecessary. Bash results are reworded like Claude Code's (trimmed output, `(Bash completed with no output)`, a failed exit as an `is_error` result starting `Exit code N`).
  - **Progress reminder:** in top-level sessions on Opus, Fable and Mythos models with native mid-conversation system messages, Anthropic's Fable 5.2 reminder ("The user hasn't heard from you in a while: …") is sent as a system message after the tool results of the 8th tool-calling step in a row with no text and no readable progress update (a thinking block whose signature header says `narration`); the steps it followed are recorded in the session's `tandemUpdateReminders` metadata so each reminder is sent again at the same place on later requests.
  - **Headers:** Effect's `traceparent`/`b3` trace headers are turned off for Anthropic API requests, which Claude Code does not send. Claude Code's headers, billing line and `tool_result` key order are set by the external Anthropic auth plugin (`~/code/opencode-anthropic-auth-v2`, `src/claude-code.ts`), not by Tandem.
- **Compaction (Claude Code 2.1.299's, for Claude models):** every Claude model in a non-bare session, main or subagent, compacts like Claude Code, using the session's model; the `keep` setting is unused, and the compaction agent's model is used only on an expired prompt cache (see the next entry). When it fires is unchanged. Other models keep their own compaction and render a Claude checkpoint as an ordinary summary without the kept group. Files: fork-owned `packages/core/src/plugin/tandem/claude/{compaction,checkpoint,restore,transcript,plugin}.ts`, `packages/core/test/claude-compaction.test.ts`; shared `packages/core/src/session/compaction.ts` (Claude delegation, main model, ignoring upstream's background summaries and not writing them for Claude sessions, and node dependencies).
  - **Summary request:** the conversation since the last compaction is split by assistant response, and the last response with everything after it is kept verbatim (fewer than two groups: nothing to compact). The summary request is the main request as it would go out, through the same hooks and Claude placement, so it reads the main prompt cache, with Tandem's version of Claude Code's lean prompt added as the last text block of the last user message. Tools stay declared and calls are never run. A "too long" rejection holds back one more group. The reply is read as Claude Code reads it.
  - **Checkpoint:** each compaction rewrites a whole-session transcript (typed user text, reply text, `[read]`/`[edited]`/`[wrote]` lines) to `transcripts/<sessionID>.md` in the scratch directory. The checkpoint, stored in the compaction message's metadata (`tandem.claude-compaction`) and read back through the same message-metadata helper as image locations, holds Claude Code's summary message with the transcript path (its closing instruction shortened to "Continue where you left off. Resume directly - pick up the task as if the break never happened."), the kept group as structured session messages (largest tool results cut to 5,000 tokens if it would not fit) and restored context: up to five files, newest modification time first (recorded on read/edit/write/patch results as `tandem.mtimes`), in Claude Code's two forms; running background shells and subagents; and a note naming skills loaded earlier.
  - **Layout:** automatic compaction is laid out as `[user: AGENTS.md reminder, summary] [system: date] [kept] [system: restored context, baseline]`, and the turn continues. After `/compact` it is `[user: summary] [kept]`, then the next user message gets the AGENTS.md reminder and Claude Code's three `/compact` records before its text, followed by `[system: restored context, baseline, date]`; a turn that continues past a mid-turn `/compact` gets the automatic layout. Models without native system messages get each system item as a `<system-reminder>` at that position.
- **Compaction on a cold prompt cache (Claude models):** the summary request above is the main request unchanged so that it reads the prompt cache. When the cache no longer holds the conversation (the last measured request is older than the model's `cache.ttl`, five minutes when unset, or went to another model or, apart from per-turn effort switches, another variant), a small request is sent instead, to the compaction agent's model or, when it names none, Claude Sonnet 5.5 on the session's provider. It is a transcript of everything but the last response group, with long tool inputs and outputs shortened by fixed rules, and has no tool definitions or cache breakpoints; the last group is kept verbatim as usual. If the summary model rejects the transcript as too long, the usual request goes out instead. The compaction message's metadata records the model and the replaced context's size under `tandem.compaction-pruned`. Details (cold-cache conditions, request shape, shortening rules): `packages/core/src/plugin/tandem/claude/README.md`. Files: fork-owned `packages/core/src/plugin/tandem/claude/{cold,compaction,restore}.ts`, `packages/core/src/plugin/tandem/prune.ts`, `packages/core/test/{claude-held,tandem-prune}.test.ts`.
- **Idle compaction: a summary held before the cache expires (Claude models):** when a main session whose last request was at least 180,000 tokens goes idle, the Claude plugin's `experimental.idle` hook starts a timer for three minutes before its prompt cache expires (a tenth of the lifetime if shorter). If the model has given no newer response by then, it sends a manual compaction's own summary request: core compaction registers a per-location writer that loads the context the runner gives `/compact` and calls the same fork-owned request function through core's own stream and budget, so the request is everything but the last response group plus the prompt, and reads the cache. The writer sends nothing when the cold-cache check above says another model or variant selected since the last response left the cache cold. Only its usage is published to the session. Files: fork-owned `packages/core/src/plugin/tandem/claude/{held,plugin,compaction,cold}.ts`, `packages/core/src/plugin/tandem/request-dump/transport.ts` (the check below), `packages/core/test/{claude-held,claude-held-guard}.test.ts`; shared `packages/core/src/session/compaction.ts` (one statement registering the writer).
  - **Held summary:** the summary is written to `tandem-held-summaries/<sessionID>.md` in the data directory, and the session's metadata gets `tandemHeld: { assistantID, at }`. The request keeps the cache alive for another lifetime, so the cold-cache check, the context button's countdown and the send dialog count from `at`. A compaction uses a held summary instead of any request while the session's last response is still the one it was written before, and keeps that response verbatim as usual. The next completed turn discards it, and a device asleep at the timer skips it.
  - **Sent only when it will read the cache:** nothing is sent, and the reason is only logged (`idle compaction not sent`), when the provider's selected login (the newest if none is selected) differs from the one when the session went idle, since a cache belongs to one account, or when the request as it would go out does not continue the session's last main request as sent. Each main request of at least 400,000 characters is remembered in memory, as it leaves after every hook, as hashes of its settings and of each message and content block; the billing line, cache markers, `max_tokens`, `stream` and `metadata` are left out. The summary request must have the same settings, tools and system prompt, the same messages, the last one's blocks unchanged at its start, and something added. Otherwise it is answered with a provider-style 400 in place of sending, which fails without a retry. After a server restart nothing is remembered, so no idle compaction is sent until the session's next turn.
  - **Failures:** what goes wrong is written to the session's metadata as `tandemHeldFailed: { at, message }` for clients to show, until the next turn ends: no registered writer, a request that failed or was rejected as too long (no attempt starts once the cache has expired, so that no retry pays full price), a summary that could not be stored, or a timer that could not be set. A request that read less than half of its input from the cache is reported too, with how many tokens were written to the cache and how many were sent uncached, and it and a missing writer turn idle compaction off until the server restarts.
- **Trimmed tool results (Claude models):** when a session's metadata has `tandemTrimNext: true`, the Claude plugin's `prompt` hook replaces it with `tandemTrimBefore: <that prompt's message ID>`. From then on every request shortens the tool results before that prompt with the same rules as the cold-cache transcript, before the Claude layout, so the shorter prefix is cached as usual. A later trimmed prompt moves the cut forward; compaction replaces the messages it applied to. If the hook fails, the prompt goes out and the failure is reported under `tandemHeldFailed` like an idle compaction's. Details: `packages/core/src/plugin/tandem/claude/README.md`. Files: fork-owned `packages/core/src/plugin/tandem/claude/plugin.ts`, `packages/core/src/plugin/tandem/prune.ts`, `packages/core/test/tandem-prune.test.ts`.
- **Narration display:** with adaptive thinking, Claude's mid-turn status updates to the user arrive as signed `thinking` blocks; only the block type inside the signature (base64 protobuf: field 2 → field 1 → field 8, `"narration"`) tells them apart. Every session-ui timeline shows those blocks as assistant text with an accent-colored start bar, so they stay visible when thinking is hidden or collapsed and remain distinguishable from ordinary text. A block shows as thinking while it streams and switches once its signature arrives. Display only: stored parts and the signed blocks sent back to Anthropic are unchanged. The TUI is not covered. Files: fork-owned `packages/session-ui/src/timeline/tandem-narration.ts`; shared `packages/session-ui/src/timeline/projection.ts` (import and one wrap of the reactive projection's message input), `packages/session-ui/src/message/current-message.tsx` (layout-neutral `data-tandem-narration` wrapper around narration text only); fork-owned `packages/gui-plugins/src/tandem/narration.css` (accent bar).
- **Thinking context management:** on the `anthropic` provider, a fork-owned plugin's `http.request` hook adds `clear_thinking_20251015` with `keep: "all"`, ahead of any compaction edits, and its beta to Claude Messages requests whose final thinking mode is `enabled` or `adaptive`. Other providers serving Claude do not get it. Files: fork-owned `packages/core/src/plugin/tandem/claude/clear-thinking.ts`; shared `packages/core/src/plugin/internal.ts` (registration).

Each retry and continuation is its own file. Coverage: native HTTP routes through a decorated injected HTTP client, WebSocket frames through `experimental.ws.handshake` and `experimental.ws.send` hooks of a plugin registered last (including reused sockets), and AI-SDK providers at the terminal global `fetch`, so custom-fetch rewrites are included. While enabled, a scoped global-`fetch` observer is installed for attributed AI-SDK calls only. A custom fetch that bypasses global `fetch` is recorded as `custom-fetch-input-unverified`, and streaming bodies are marked as omitted rather than consumed. Credentials are redacted and write failures never fail the request. Imagegen's own image API calls are not captured. Files: fork-owned `packages/core/src/plugin/tandem/request-dump/{record,transport,sdk-fetch,plugin}.ts`; shared `packages/core/src/effect/app-node-platform.ts`, `packages/core/src/session/model-request.ts`, `packages/core/src/aisdk.ts` (marked one-line seams), `packages/core/src/plugin/internal.ts` (registration).

### Temporary Upstream Bug Fixes

Fixes for bugs present in pristine upstream, marked `UPSTREAM-DIVERGENCE(temporary)`. Remove each with its markers when upstream ships an equivalent fix. None of those below was fixed upstream as of `88ca792e02` (2026-11-18).

- **Pending prompt stuck after a missed update:** the event stream does not replay events missed while it is down. A sent prompt whose admission or delivery update was missed stayed "Pending" with its move and delete buttons for good (they failed with "Request failed"), and the session looked busy; upstream's reload of the open session's messages and pending prompts on reconnect kept the row, because the prompt still counted as unacknowledged. A successful send now acknowledges the prompt too. Files: `packages/client/src/solid/data.ts`.
- **Reading position lost when switching away** ([anomalyco/opencode#42806](https://github.com/anomalyco/opencode/issues/42806)): upstream only remembers whether you were at the newest messages. Scrolled up, switching tabs and back jumped to the top of the loaded history, and switching sessions and back jumped to the newest messages. Each session now remembers the message at the top of the screen and returns to it. Sessions left at the newest messages still open there. Files: `packages/app/src/session/timeline/{virtualizer.tsx,interaction.ts,follow.ts}`.
- **Menu actions that do nothing on touch:** three options-menu items acted on finger-up, and the tap's trailing click then landed on what had just appeared or on what lay under the menu item. Each now acts after the menu has closed.
  - **Session header options menu, Delete:** the delete dialog opened under the finger, and the click on its backdrop closed it at once. Rename in the same menu already waited for the menu to close. Files: `packages/app/src/session/timeline/message-timeline.tsx`.
  - **Session tab context menu (long-press or right-click), Delete:** the same, with the same Rename precedent. Files: `packages/app/src/shell/titlebar/tab-nav.tsx`.
  - **Connect dialog account list, Remove:** the row, menu included, was replaced by the "Remove …?" prompt, and the click landed on Add account (opening the connect screen), another account (switching to it), or outside the dialog (closing it). Files: `packages/app/src/providers/connect/dialog.tsx`.
- **Newest messages hidden when the chat area gets shorter:** upstream keeps the scroll offset when the chat area shrinks, so at the newest messages, the Android keyboard (which shrinks the app) or a shorter window hid the last lines behind the composer. At the newest messages, the chat now stays at the end; scrolled up, it stays where it is. Files: `packages/app/src/session/timeline/interaction.ts`.
- **Earlier messages hidden after an undo in a forked session:** while an undo is in effect, upstream hides messages by comparing their IDs as text against the undone message's ID. Messages copied into a fork get IDs ending in an unpadded sequence number (`_745` sorts after `_1070`), so the chat hid most of the history before the undo point, and the user-prompt list used for navigation lost the same prompts. The app and the TUI transcript now cut the list at the undone message's position. Files: `packages/app/src/session/session-domain.ts`, `packages/app/src/session/timeline/controller-projection.ts`, `packages/tui/src/routes/session/rows.ts`.
- **Home project dropdown keeps the old project's name:** on narrow screens, switching from one project to another left the dropdown label on the first one (the search placeholder and the sessions changed). The label was a plain string returned from an untracked `<Show>` callback; it is now a reactive expression. Files: `packages/app/src/home/projects/view.tsx`.
- **New-session project picker shows the wrong project for a worktree folder:** the picker took the first project whose folder or worktree list matched the draft's folder. `~/code/Tandem-v2` shares Tandem's first commit, so the server lists it as a worktree of the Tandem project; with Tandem earlier in the list, the label and checkmark always showed Tandem even though the draft was in Tandem-v2. An exact folder match now wins before the worktree match. Files: `packages/app/src/new-session/project/selector.tsx`.
- **Android keyboard cannot delete a mention:** mentions are read-only spans, and an Android keyboard's Backspace right after one does nothing; the caret can then end up inside the mention, where no editing works. With `view.nativeEditing`, a zero-width gap follows each mention, Backspace over the gap removes the whole mention, and a caret inside a mention or before its gap moves after the gap. The parser and cursor ignore the gap. Files: fork-owned `packages/app/src/composer/editor/tandem-native-mentions.ts`; shared `packages/app/src/composer/editor/editor.tsx` (install call, gap restoration on render and input, gap-free parsing and cursor).

### Upstream Limitations Worked Around In Fork-Owned Code

No shared file changes; listed so a sync can simplify these if upstream changes.

- Core credential resolution (`packages/core/src/integration.ts`) reads, refreshes and persists without serialization. The Claude auth plugin keeps a process-wide rotation map (a failed refresh is dropped from it so the next request retries), and imagegen keeps a per-credential mutex.
- A tool is marked settled before its success event is validated and published. Public `Tool.Metadata` allows values that durable events reject, so imagegen omits undefined metadata values.
- An external provider loaded from source cannot pass its `LanguageModel` to a packaged host (class identity differs). The auth plugin's `src/insecure-provider.ts` rebuilds a host model before preparing requests.
